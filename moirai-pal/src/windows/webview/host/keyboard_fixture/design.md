# Installed physical-key policy experiment

Metis f1523a43/run38821192294 receives native Alt+Shift+S but retains only
Selected, D→Dark/Ok and Alt/Shift→Ignored/Ok in the Rust document stream.
Its missing terminal prevents absence or browser-interception conclusions.
This fixture tests a candidate boundary; it changes no production policy.

## Controlled variation

One test algorithm runs in three separate fresh-profile invocations. Default
reads the event property without a setter. EnableS calls the setter with true;
SkipS calls the same setter with false. The latter two match the extra SDK
call, so setter timing can be distinguished from its Boolean argument.
Each invocation keeps the existing30-second operation,60-second nextest and
120-second CLI bounds. The20-minute workflow bound remains unchanged.

The additional test-owned handler operates synchronously on actual event args.
It checks fresh key/system-key down, VK_S, Alt+Shift held, Ctrl clear and both
Win keys clear. It records actual before/after browser policy, Handled, raw
lParam and five native key states. It never sets Handled or global settings.
Unsupported Args2 and every getter/setter/removal failure remain failures;
they cannot pass as missing S. The passive diagnostic callbacks stay exact.
Microsoft documents controller→browser-feature→content ordering and that
false skips browser-feature processing while preserving content propagation:
[Args2 contract](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2acceleratorkeypressedeventargs2?view=webview2-1.0.4191.47).

## Real inputs and observed output

All cells load the same compiled Rust payload and inject D,S,P through the
actual focused descendant's HKL mappings. A chord is six physical INPUTs in
one ordered SendInput call, with cached mappings for corresponding releases.
This differs from Metis's separately observed insertion calls and does not
establish equivalent scheduling. Both requested vectors and actual callback
scan/extended/up bits are retained. Partial admission immediately captures
LastError; only unmatched downs are released, in reverse press order. For
prefix k, an inverse at u is owed exactly when d<k≤u. All seven prefixes of
the six-record sequence have an exhaustive analytical oracle.

The test pumps actual native release observations and Rust bridge notices;
it performs no input retry, synthetic DOM event, sleep or deadline renewal.
Ready occurs once, Key notices have contiguous positive sequences, and one
Closed follows actual DOM/bridge listener retirement. The original received
JSON is preserved and charged independently from producer canonical bytes.
DOM active/retained counts and bridge retained count must all be zero.
Handler removal precedes host close, actual Destroyed and package/profile
removal. Failed ownership confirmation retains the directories.

## Interpretation and verification

The comparison requires equal actual runtime versions, recipient layouts,
all mapped strokes, and archived payload hashes. D/P are positive content
controls. SkipS requires actual trusted S metadata and one real successful
property transition with Handled false. Default never assumes S disappears.
Default/EnableS absent and SkipS present supports a bounded property-specific
difference; EnableS/SkipS present with Default absent supports a setter-path
difference. All three present means the failure is not reproduced.

Trailing P, contiguous notices and Closed establish an observed prefix,
not a native-input/IPC drain barrier or absolute absence of future events.
No standalone outcome establishes the Metis cause. Real consumer A/B and both
unchanged complete Metis journeys remain required before production promotion.
Portable wire/release tests and cross-compilation are distinct from installed
Windows execution. Original eight modes,16/64 assertions and Rust bridge path
remain unchanged; the new generated payload has separate exact admission.
