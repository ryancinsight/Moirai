# Rayon/Tokio Gap Audit

## Scope

This audit covers the active unified-scheduler comparison scope:

- Public result-bearing task handles: `Moirai::spawn_fn`, `Moirai::spawn_async`, and `TaskHandle::join`.
- Completion-only parallel work: `Moirai::scope`.
- Indexed data-parallel work: `Moirai::for_each_indexed` and `Moirai::map_reduce_indexed`.
- Mixed scheduler work: completion-only sync fan-out, async result handles, and indexed reduction in one runtime.
- Batch quiescence: `Moirai::join` and `Moirai::has_work`.
- Transport receive memory behavior: `ArchiveView` over transport-owned bytes.
- Async timeout composition: `Timeout<F>` stores the concrete future inline.
- Async timer cancellation: `TimerWheel` tracks cancelled timer IDs lazily and verifies that cancelled expired timers do not wake.
- Native async I/O extension futures: `AsyncReadExt::read_exact` and `AsyncWriteExt::shutdown` borrow caller-owned buffers/writers directly, preserve partial read progress on cancellation, and are covered by value tests.
- Feature-gated Tokio I/O trait compatibility: transparent `TokioCompat<T>` and `MoiraiCompat<T>` wrappers preserve byte semantics in both directions, with `async_io_compat_comparison` measuring native extension futures against Tokio extension traits over the same in-memory readers and writers.
- Async file and directory facade: `moirai_async::fs::{read, write, append, metadata, rename, remove_file, copy}` have value-checked 64 KiB Tokio file facade read, write, append, metadata, rename, remove, and copy comparisons in `async_fs_comparison`; `moirai_async::fs::{create_dir, create_dir_all, remove_dir, remove_dir_all}` have value-checked Tokio directory facade comparisons in `async_fs_dir_comparison`; `write`, `append`, `metadata`, `rename`, `remove_file`, and directory operations delegate to PAL platform operations, and `copy` delegates to the PAL platform copy operation instead of allocating a user-space transfer buffer.
- Moirai-owned network facade value semantics: TCP loopback read/write, write-side shutdown EOF, bounded write backpressure, read readiness before peer data, pending-read cancellation safety, and UDP loopback send/receive are covered by value-sensitive module tests; TCP loopback accept/echo, persistent stream echo, write shutdown, write backpressure, read readiness, and pending-read cancellation safety have Tokio comparison rows in `async_tcp_comparison`, `async_tcp_backpressure_comparison`, `async_tcp_readiness_comparison`, and `async_tcp_cancel_safety_comparison`; UDP loopback receive has a Tokio comparison row in `async_udp_comparison`.
- Bounded channel transport: `moirai_core::channel::mpmc` has value-checked `bounded_channel_matrix` rows against `tokio::sync::mpsc`, with executable `moirai_mpmc` and `tokio_mpsc` row names.
- PAL async file facade: `moirai-pal::fs::AsyncFile` has value-semantic roundtrip, seek, metadata, read-to-end, platform-write, platform-append, path-metadata, path-rename, path-remove, directory create/remove, recursive directory create/remove, and platform-copy tests.
- PAL async socket self-wake fallback: `moirai-pal::net::AsyncTcpListener`, `AsyncTcpStream`, and `AsyncUdpSocket` self-wake when no active reactor is installed, and register reactor wakers when one is active.
- PAL reactor task-handle completion: `IoReactor::spawn` publishes completion through per-task atomic state and wakes the awaiting `TaskHandle`.
- PAL reactor task queue avoids dynamic future dispatch: queued reactor futures use bounded inline storage plus monomorphized poll/drop functions instead of `Pin<Box<dyn Future<Output = ()>>>`; oversized futures use a typed boxed fallback stored behind the same monomorphized path.
- PAL platform reactor dispatch is static: `create_reactor` returns the compile-target `PlatformReactor` type instead of `Box<dyn Reactor>`.
- Public scheduler task dispatch is concrete: `moirai-core::ScheduledTask` uses `INLINE_SCHEDULED_TASK_WORDS` inline storage with monomorphized execute/drop/context functions, and `WorkStealingScheduler` plus `NumaAwareScheduler` queue `ScheduledTask` values instead of `Box<dyn BoxedTask>`.
- Standalone scheduler work-stealing storage is contiguous: `moirai-scheduler::ChaseLevDeque` stores `ScheduledTask` values in `UnsafeCell<MaybeUninit<T>>` ring slots instead of allocating one `Box<T>` per queued item. Reclamation is monomorphized by policy: default `QuiescentReclaim` uses zero-sized state and guard; opt-in `SharedEpochReclaim` uses one active-access counter to block shared reclamation while push, pop, or steal may hold an array pointer.
- Standalone deque reclamation policy overhead is measured by `thread_schedule_comparison -- standalone_deque_reclaim_policy`; the diagnostic keeps `QuiescentReclaim` as the production default and `SharedEpochReclaim` as an explicit opt-in policy.
- PAL epoll reactor wake: Linux `EpollReactor::wake` uses an `eventfd` registered with epoll instead of a no-op wake path.
- Async executor queueing: heterogeneous queued futures use monomorphized poll/drop function pointers instead of `dyn Future`.
- Iterator support infrastructure: `ThreadPool` queues `ErasedThreadJob` values instead of boxed `dyn FnOnce` jobs.
- Iterator channel fusion infrastructure: splitters and mergers store one concrete `FusableChannel` type per instance instead of boxed channel trait objects.
- Iterator streaming infrastructure: `StreamingIter<T, F>` stores a concrete producer and `VecDeque` FIFO buffer; the unused boxed-future base trait is removed.
- Iterator SIMD surface is generic: `SimdSliceIter<T>` is backed by the sealed `SimdScalar` contract, stale backup source is removed, and `iter_simd_comparison` verifies generic add and dot rows against scalar references.
- Utility SIMD surface is generic: `moirai_utils::simd` exposes sealed `SimdScalar` and `SimdReal` traits plus `add`, `mul`, `dot`, `sum`, `mean`, `variance`, and `matrix_mul_square<T, const N>` instead of public type-suffixed kernels; native ISA code is private backend detail, and non-lane-multiple `f32` slice lengths use native vector prefixes plus scalar tails with dispatch-accounting tests.
- Iterator indexed source cardinality, collection, and composition: `moirai-iter::parallel::IndexedParallelIterator` exposes `len`, `is_empty`, `collect_into_vec`, `unzip_into_vecs`, `interleave`, `interleave_shortest`, `step_by`, `by_exponential_blocks`, and `by_uniform_blocks` for exact-size source iterators, with owned `Vec<T>` iteration stored by value through `VecParIter<T>` instead of `Arc<Vec<T>>`; owned vector `collect_into_vec` bulk-moves values into caller-provided spare capacity without cloning, pair-source `unzip_into_vecs` moves both sides into caller-provided vectors without clone bounds, indexed interleave adapters move values from both inputs through concrete generic adapter types, indexed `step_by` performs fixed-stride source selection without clone bounds, and indexed block adapters preserve logical output order through concrete generic adapters with zero-sized policy markers and non-zero uniform block validation.
- Iterator collect-vec-list terminal: `moirai-iter::parallel::ParallelIterator::collect_vec_list` returns Rayon's public `LinkedList<Vec<T>>` terminal shape, moves the logical stream into one vector segment without clone bounds, and verifies flattened output equivalence against Rayon without claiming equivalent internal segment partitioning.
- Iterator borrowed vector source: `moirai-iter::parallel::IntoParallelRefIterator for Vec<T>` borrows `&T` values with `T: Send + Sync + 'data`, matching the audited Rayon reference boundary without requiring `T: Clone + 'static`.
- Iterator scoped chunk helper: `moirai-iter::iter_ops::ParallelIter` owns `Vec<T>` directly, borrows scoped immutable chunks without `Arc<Vec<T>>`, accepts non-`'static` closures, and gates scoped OS-thread fanout behind the bounded scheduler batch capacity.
- Iterator cache helper: `moirai-iter::cache::ZeroCopyParallelIter` borrows input slices and map closures directly through scoped chunks without `Arc` allocation, moves reduce partials through owned pair compaction, accepts non-`Clone` reducer closures, and gates scoped OS-thread fanout behind one scheduler batch of cache chunks.
- Iterator execution contexts: direct `execute_iter` paths move owned chunks and accept non-`Clone` items instead of cloning chunk slices before scheduling.
- NUMA iterator helper: `moirai-iter::numa::NumaContext` and `NumaIter` consume owned batches for map and reduce without clone-bound chunk materialization.
- Distributed iterator helper: `moirai-iter::distributed::DistributedContext` consumes owned partitions for partition/map/reduce helper paths and returns value-semantic map results.
- Multi-system iterator helper: `moirai-iter::multi_system::MultiSystemContext` consumes owned partitions through the unified scheduler, distributes real partition iterators, and returns value-semantic heterogeneous map results without clone-bound direct item paths.

Drop-in API compatibility with every Tokio I/O type or every Rayon `ParallelIterator` adapter is not part of this scheduler audit. Those are ecosystem extension goals, not active gaps in the unified scheduler comparison.

## Verdict

No active comparison gap remains in the official scheduler/result-handle/indexed-reduction scope. Each accepted comparison has:

- A real Moirai API path.
- A real Tokio or Rayon reference path where the semantics match.
- A value assertion before timing.
- A bounded Criterion benchmark target.
- A `benchmark_contracts` test that protects benchmark shape, value semantics, and source invariants.

The 2026-06-01 audit pass keeps that verdict unchanged for covered semantics and records the remaining work as deferred ecosystem or cleanup gaps. These gaps are not scheduler comparison failures because they either require non-equivalent API compatibility work or affect inactive legacy files rather than compiled runtime dependency boundaries.

## Acceptance Criteria

- Every competitive benchmark path asserts a closed-form or reference-computed value before black-boxing.
- Criterion targets use explicit sample, warm-up, and measurement windows.
- Public result handles remain separate from completion-only batch rows.
- Mixed scheduler rows must use the same closed-form result across Moirai and Tokio/Rayon reference paths.
- Tokio and Rayon are benchmark, test, and comparison-example dependencies only; production dependency sections do not import either runtime.
- Hot-path scheduler task dispatch does not reintroduce `Box<dyn FnOnce>`, raw heap-job vtables, boxed futures, or dynamic execution-policy dispatch.
- Scoped scheduler jobs buffer inline `ScheduledJob` values instead of boxed `dyn FnOnce` closures.
- Iterator thread-pool jobs queue `ErasedThreadJob` values with monomorphized run/drop functions instead of `Box<dyn FnOnce>` queue items.
- Iterator channel fusion splitters and mergers store concrete channel types and do not expose placeholder hash distribution or non-executing pipeline stages.
- Iterator streaming producers remain generic and FIFO buffering does not use `Vec::remove(0)`.
- Iterator `iter_ops::ParallelIter` must not reintroduce `Arc<Vec<T>>`, closure `Arc` routing, unscoped `thread::spawn`, or `'static` closure bounds on map/reduce.
- Iterator `ZeroCopyParallelIter::map` must not reintroduce `Arc` wrappers for borrowed data or closures. `ZeroCopyParallelIter::reduce` must not reintroduce cloned intermediate chunks, cloned reducer closures, or an ungated scoped OS-thread fanout path for cache-resident borrowed reductions.
- Iterator indexed `collect_into_vec`, `unzip_into_vecs`, `interleave`, and `interleave_shortest` must not clone owned source values and must retain non-`Clone` move tests, benchmark-contract source guards, and same-run Rayon benchmark coverage. Iterator `collect_vec_list` must retain non-`Clone` movement, flattened-output value checks, benchmark-contract source guards, same-run Rayon benchmark coverage, and the documented segment-count non-claim. Iterator `zip_eq` must retain equal-length output tests, mismatch panic tests, benchmark-contract source guards, and same-run Rayon benchmark coverage. Iterator `partition_map` must retain local `Either<L, R>` routing, side-local order tests, benchmark-contract source guards, and same-run Rayon benchmark coverage. Iterator `try_reduce_with` must retain sealed `TryStreamItem` routing, `Option` and `Result` value tests, mapped fast-path source guards, and same-run Rayon benchmark coverage. Iterator `positions` must retain owned, borrowed, mapped-stream value tests, mapped fast-path source guards, and same-run Rayon benchmark coverage. Iterator borrowed vector `par_iter` must not reintroduce `T: Clone + 'static` bounds and must retain non-`Clone` borrowed map unit, benchmark-contract, and same-run Rayon benchmark coverage.
- Iterator execution contexts must not reintroduce `chunk.to_vec()`, `item.clone()` map execution, or `T: Clone` direct map bounds.
- NUMA iterators must not reintroduce clone-bound direct map execution, cloned chunk materialization, or cloned reduction functions for owned batches.
- Distributed iterators must not reintroduce clone-bound owned partitions, placeholder empty map execution, or existence-only distributed iterator map tests.
- Multi-system iterators must not reintroduce clone-bound owned partitions, slice `to_vec()` partitioning, cloned map functions, placeholder empty distribution, placeholder monitoring comments, or existence-only heterogeneous map tests.
- Iterator base APIs do not expose unused `Pin<Box<dyn Future<...>>>` execution traits.
- Timer-wheel cancellation must return value-sensitive cancellation results, suppress canceled waker wakeups, and avoid placeholder false returns.
- Async file facade comparison must assert Moirai bytes and Tokio bytes against the same source bytes before timing for read, write, append, metadata, rename, remove, and copy rows. Async directory facade comparison must assert single directory create/remove state and recursive directory create/remove marker-file state before timing.
- Tokio I/O trait compatibility wrappers must be feature-gated, transparent, value-tested in both directions, and benchmarked against native extension futures over the same payloads before any Tokio trait-compatibility claim.
- Async network facade tests must assert TCP and UDP payload equality plus byte/packet counters; TCP and UDP facade benchmarks must assert Moirai and Tokio payload equality before timing; TCP write-backpressure benchmarks must assert both paths write positive bytes before timing; TCP read-readiness benchmarks must assert `Poll::Pending` before peer data and exact payload bytes after release; TCP pending-read cancellation benchmarks must assert unchanged caller buffers after dropping a pending read future and exact payload bytes after release; these tests do not imply Tokio reactor-native drop-in compatibility.
- Bounded channel matrix rows must assert the same closed-form transferred-item checksum before timing each Tokio MPSC and Moirai MPMC path.
- PAL async socket no-active-reactor fallback must wake the current task before returning `Pending`, preventing `block_on` deadlock on delayed readiness.
- PAL reactor task handles must return `Ready(())` after the spawned task completes; tests must reject placeholder pending-only handles.
- PAL reactor task queues must not use `Pin<Box<dyn Future<Output = ()>>>`; heterogeneous queued futures must use bounded inline storage and monomorphized poll/drop function pointers, with typed boxed fallback only for oversized futures.
- PAL platform reactor selection must be static for the compile target and must not return `Box<dyn Reactor>`.
- Public scheduler task APIs must not expose `Box<dyn BoxedTask>`, `dyn Scheduler`, `TaskSlot`, or `Pin<Box<dyn Future>>`; heterogeneous scheduler work must flow through `ScheduledTask`.
- Standalone scheduler deque storage must not reintroduce `Box<[AtomicPtr<T>]>`, `Box::into_raw(Box::new(item))`, or `Box::from_raw(item_ptr)` per-item queue nodes.
- Standalone deque reclamation-policy diagnostics must assert the drained sum for quiescent and shared epoch policy rows before timing.
- Work-class routing remains sealed, zero-sized, and monomorphized through `WorkClass` marker types.
- Utility SIMD public APIs must stay generic over sealed scalar traits, retain vector-prefix/tail coverage for non-lane-multiple `f32` lengths, and must not reintroduce public type-suffixed vector kernels, lane-multiple-only dispatch accounting, or matrix dimensions encoded only in function names.
- Documentation, backlog, checklist, changelog, performance results, and benchmark contracts reference the same active comparison scope.
